# XAI Analysis and SXGA Research Pipeline

## Overview

This repository supports research on Explainable Artificial Intelligence (XAI) for psychological and mental-health-related classification tasks. It includes the original survey-analysis workflow and a reconstructed evaluation pipeline for selected public datasets.

The project investigates model performance, probability calibration, feature explanations, and the proposed Support Vector Machine–XGBoost hybrid architecture (SXGA).

**Important:** The SXGA implementation is a reconstruction of the described method, not a verified copy of the lost original source code. All results must be generated by running the code and must not be assumed to reproduce previously reported values.

## Project Components

### 1. Original Survey Analysis

The primary survey dataset contains 196 initial responses. According to the study protocol, one response was excluded because consent was not provided, leaving 195 eligible responses.

The analysis covers three psychological tasks:

- Depression classification using DASS-21 depression measures.
- Life-satisfaction classification using SWLS.
- Personality classification using a Big Five measure.

The final target definitions, questionnaire scoring, missing-data rules, and predictor exclusions must be verified against the original questionnaire and dataset before analysis.

The original survey must remain separate from all public datasets. No synthetic expansion of the survey to thousands of observations is performed.

### 2. Public-Dataset Evaluation

The public-cohort pipeline is provided in `public_cohort_sxga.py`.

It supports independent evaluation of:

- **NHANES 2021–2023:** Depression-screening classification based on the PHQ-9 questionnaire.
- **COVIDiSTRESS:** Distress-related classification, subject to the variables and scoring rules in the selected release.
- **OpenPsychometrics Big Five:** Personality classification, subject to the instrument, available response variables, and documented scoring rules.

Each cohort is processed and evaluated independently. The datasets are not pooled, and a model trained on one cohort is not automatically evaluated on another cohort.

The latest identifiable release should be used when its documentation and target variables are suitable. The actual release date, download source, and data-cleaning decisions must be recorded for reproducibility.

### 3. Models

The pipeline supports comparisons between:

- Logistic Regression
- Linear Support Vector Machine (SVM)
- Random Forest
- XGBoost
- Reconstructed SXGA

SXGA follows the described design:

1. Calculate linear SVM decision margins.
2. Augment the feature representation with the margins.
3. Calculate raw margin residuals using the binary target minus the SVM margin.
4. Train XGBoost regressors to predict residuals.
5. Combine the SVM margins and predicted residual corrections.
6. Normalize the corrected class scores into probabilities.

This residual formulation is a methodological reconstruction and should be validated through ablation experiments before being presented as the definitive original algorithm.

### 4. Explainability

The broader research workflow uses:

- SHAP global and local explanations
- LIME explanations
- Feature-importance analysis
- Counterfactual explanations, where implemented
- Explanation-consistency analysis

The public-cohort script currently focuses on predictive evaluation. It does not yet implement the full SHAP/LIME explanation workflow or calculate the study's final Explanation Consistency Score (ECS). Expected Calibration Error (ECE) and ECS are different metrics and must not be used interchangeably.

## Running the Public-Cohort Pipeline

### NHANES

Run:

```bash
python public_cohort_sxga.py --run-nhanes --outdir results
```

The script downloads the NHANES depression-questionnaire and demographic files and constructs a PHQ-9 screening target. A score of 10 or higher is treated as screen-positive; this is a screening threshold, not a clinical diagnosis.

Questionnaire items used to construct the target are excluded from the predictors to prevent direct target leakage.

### COVIDiSTRESS

Download a dataset release and its documentation from the official project source:

https://covidistress.github.io/data/

Then configure the actual CSV path, target column, positive class if applicable, and questionnaire-item exclusions:

```bash
python public_cohort_sxga.py \
  --covid-csv data/covidistress.csv \
  --covid-target VERIFIED_TARGET_COLUMN \
  --covid-positive-value VERIFIED_POSITIVE_LABEL \
  --covid-drop-cols "TARGET_ITEM_1,TARGET_ITEM_2" \
  --outdir results
```

Replace the example placeholders with verified column names and labels. Do not infer a depression target from a general distress measure without a defensible scoring definition.

### OpenPsychometrics Big Five

Download a suitable raw-data release and its codebook:

https://openpsychometrics.org/_rawdata/

Run the adapter after identifying the instrument and target definition:

```bash
python public_cohort_sxga.py \
  --bigfive-csv data/bigfive.csv \
  --bigfive-target VERIFIED_TARGET_COLUMN \
  --bigfive-positive-value VERIFIED_POSITIVE_LABEL \
  --bigfive-drop-cols "TARGET_ITEM_1,TARGET_ITEM_2" \
  --outdir results
```

For multiclass targets, omit the positive-value argument. Verify that the target represents the intended personality construct and that all target-derived variables are excluded from the predictors.

## Validation and Preprocessing

The public-cohort pipeline uses repeated stratified cross-validation, with five folds and five repeats by default.

Preprocessing is fitted within each training fold. The pipeline includes missing-value imputation, numerical scaling, and categorical encoding.

Any resampling method must be restricted to training data. Calibration procedures must also avoid leakage between model fitting and calibration evaluation.

Before interpreting results, check:

- The number of observations retained after cleaning.
- Class counts and class imbalance.
- Missing questionnaire responses.
- Target scoring and class labels.
- Questionnaire-item and identifier exclusions.
- Whether all folds completed successfully.
- Whether probability columns align with the correct class labels.

## Output Files

The public-cohort pipeline writes its outputs to the specified results directory.

- `*_fold_results.csv`: individual cross-validation results.
- `*_summary.csv`: mean and standard deviation of the evaluation metrics.
- `*_metadata.json`: cohort metadata, target definition, sample size, and exclusions.
- `cohort_manifest.csv`: overview of the evaluated cohorts.

Metrics include accuracy, balanced accuracy, macro-F1, ROC-AUC where applicable, top-label ECE, Brier score, and log loss.

## Reproducibility and Reporting

Keep the following records for each experiment:

- Dataset source, version, and access date.
- Original and final sample sizes.
- Questionnaire and target-scoring definitions.
- Missing-data handling and excluded variables.
- Model hyperparameters and random seeds.
- Cross-validation design and fold-level results.
- Calibration method and calibration metrics.
- Explanation-generation settings and ECS definition, when implemented.

Do not report unverified values as reproduced experimental findings. Results from different datasets should be described separately because their populations, instruments, class distributions, and target definitions may differ.

Repeated cross-validation folds are not independent observations; statistical comparisons must account for the dependence between folds.

## Research Limitations

The current public-cohort script is a predictive evaluation foundation rather than a complete end-to-end reproduction of every manuscript analysis. Full SHAP/LIME generation, the final ECS calculation, counterfactual evaluation, and rigorous nested calibration comparison require additional implementation and validation.

The findings are intended for research and methodological evaluation, not clinical diagnosis or individual treatment decisions.
